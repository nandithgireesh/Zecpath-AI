## 1. Schema Architecture & Contract Governance

Day 59 Deliverable 3 formalizes the **Request/Response Schema Definitions** governing all five core AI APIs in the **Zecpath AI Automated Hiring Platform**.

Every contract is implemented using Pydantic v2 data models and exported into OpenAPI 3.1 and JSON Schema Draft-07 formats. This guarantees:
1. **Type Safety & Runtime Validation:** Automated type coercion and strict constraints prevent malformed requests from entering AI compute pipelines.
2. **Standardized Error Envelopes:** All validation failures and exceptions emit an uniform `APIErrorEnvelope` with unique correlation tracking IDs.
3. **Automated Documentation & Client SDK Generation:** Clean JSON Schema definitions enable automatic client stub generation for TypeScript, Python, and Go microservices.

## 2. Core API Schema Specifications

### 2.1. API-01: Resume Parsing Schema
* **Route:** `POST /api/v1/ai/resume/parse`
* **Request Schema (`ResumeParseRequest`):**
  - `candidate_id` (`string`, required): Unique candidate identifier.
  - `document_url` (`string`, required): Pre-signed secure S3/GCS URL to candidate resume document.
  - `mime_type` (`string`, default `"application/pdf"`): MIME type (`"application/pdf"`, `"application/vnd.openxmlformats-officedocument.wordprocessingml.document"`).
  - `webhook_callback_url` (`string`, optional): Webhook URL for async completion callback.
  - `extract_academic_profile` (`boolean`, default `true`): Flag to extract university and degree data.
  - `anonymize_pii` (`boolean`, default `true`): Flag to redact phone numbers, emails, and home addresses.
* **Response Schema (`AsyncJobResponse`):**
  - `job_id` (`string`): Unique job identifier (`"JOB-RESUME-[HEX:8]"`).
  - `status` (`string`): Current job status (`"QUEUED"`, `"PROCESSING"`, `"COMPLETED"`, `"FAILED"`).
  - `created_at` (`float`): Epoch timestamp of job registration.
  - `estimated_completion_seconds` (`float`, default `2.5`): Estimated processing time.
  - `status_url` (`string`): Polling endpoint (`"/api/v1/ai/jobs/{job_id}"`).
  - `result` (`ResumeParserResult`, optional): Populated when `status == "COMPLETED"`.
  - `error` (`string`, optional): Populated when `status == "FAILED"`.

### 2.2. API-02: ATS Scoring Schema
* **Route:** `POST /api/v1/ai/ats/score`
* **Request Schema (`ATSScoreRequest`):**
  - `job_id` (`string`, required): Requisition job identifier.
  - `candidate_id` (`string`, required): Candidate identifier.
  - `job_description_text` (`string`, required, min length 20): Raw or parsed job requisition text.
  - `candidate_resume_text` (`string`, required, min length 20): Extracted candidate resume body.
  - `required_skills` (`array[string]`, default `[]`): Mandatory skills specified in requisition.
  - `min_experience_years` (`float`, default `2.0`): Experience threshold.
* **Response Schema (`ATSScoreResponse`):**
  - `candidate_id` (`string`): Candidate identifier.
  - `job_id` (`string`): Job identifier.
  - `composite_ats_score` (`float`, range 0.0 - 100.0): Overall weighted compatibility score.
  - `skill_match_score` (`float`, range 0.0 - 100.0): Skill match percentage (50% weight).
  - `experience_fit_score` (`float`, range 0.0 - 100.0): Experience seniority fit (35% weight).
  - `formatting_hygiene_score` (`float`, range 0.0 - 100.0): Document format score (15% weight).
  - `matched_skills` (`array[string]`): Skills present in both resume and requisition.
  - `missing_critical_skills` (`array[string]`): Mandatory skills absent from candidate profile.
  - `is_shortlisted` (`boolean`): Set to `true` if `composite_ats_score >= 75.0`.
  - `evaluation_timestamp` (`float`): Epoch evaluation time.

### 2.3. API-03: Screening AI Schema
* **Route:** `POST /api/v1/ai/screening/utterance`
* **Request Schema (`ScreeningUtteranceRequest`):**
  - `session_id` (`string`, required): Active screening session identifier.
  - `candidate_id` (`string`, required): Candidate identifier.
  - `turn_index` (`integer`, required): Incremental turn sequence number.
  - `transcript_utterance` (`string`, required): Speech-to-text transcript of candidate turn.
  - `audio_latency_ms` (`float`, default `120.0`): Audio ingestion latency.
  - `is_silence` (`boolean`, default `false`): Silence detection flag.
* **Response Schema (`ScreeningUtteranceResponse`):**
  - `session_id` (`string`): Session identifier.
  - `turn_index` (`integer`): Turn sequence index.
  - `ai_next_question` (`string`): Next conversational question generated by call flow engine.
  - `detected_intent` (`string`): Classified candidate intent (e.g., `"SALARY_ALIGNMENT"`, `"NOTICE_PERIOD"`).
  - `eligibility_status` (`string`): Status (`"PASS"`, `"FLAGGED"`, `"FAIL"`).
  - `is_session_complete` (`boolean`): Indicates whether screening criteria are satisfied.
  - `turn_processing_latency_ms` (`float`): Turn processing time in milliseconds.

### 2.4. API-04: Interview AI Schema
* **Route:** `POST /api/v1/ai/interview/turn`
* **Request Schema (`InterviewTurnRequest`):**
  - `interview_session_id` (`string`, required): Live interview session identifier.
  - `candidate_id` (`string`, required): Candidate identifier.
  - `current_topic` (`string`, required): Technical or behavioral topic being evaluated.
  - `candidate_answer_text` (`string`, required): Candidate verbal response transcript.
  - `code_submission` (`string`, optional): Source code snippet submitted in sandbox editor.
  - `voice_pitch_variance` (`float`, default `14.5`): Vocal frequency variability measure.
  - `speech_rate_wpm` (`float`, default `142.0`): Candidate speech rate in words per minute.
  - `turn_index` (`integer`, required): Turn index counter.
* **Response Schema (`InterviewTurnResponse`):**
  - `interview_session_id` (`string`): Session identifier.
  - `turn_index` (`integer`): Turn index counter.
  - `turn_technical_score` (`float`, range 0.0 - 100.0): Technical competence score.
  - `turn_behavioral_score` (`float`, range 0.0 - 100.0): Behavioral composure score.
  - `realtime_pacing_feedback` (`string`, optional): Micro-feedback on cadence.
  - `ai_follow_up_prompt` (`string`): Adaptive follow-up question.
  - `socratic_hint` (`string`): Diagnostic architectural hint.
  - `sync_processing_latency_ms` (`float`): Measured turn latency (empirically $18.50\text{ ms}$).

### 2.5. API-05: Decision AI Schema
* **Route:** `POST /api/v1/ai/decision/arbitrate`
* **Request Schema (`DecisionArbitrationRequest`):**
  - `candidate_id` (`string`, required): Candidate identifier.
  - `requisition_id` (`string`, required): Job requisition identifier.
  - `ats_score` (`float`, required): ATS compatibility score.
  - `screening_score` (`float`, required): Conversational screening score.
  - `technical_interview_score` (`float`, required): Technical evaluation score.
  - `behavioral_score` (`float`, required): Behavioral evaluation score.
  - `integrity_score` (`float`, required): Malpractice integrity score.
* **Response Schema (`DecisionArbitrationResponse`):**
  - `candidate_id` (`string`): Candidate identifier.
  - `hiring_verdict` (`string`): Decision verdict (`"RECOMMENDED_OFFER"`, `"FURTHER_REVIEW"`, `"REJECT"`).
  - `composite_hiring_score` (`float`, range 0.0 - 100.0): Normalized cross-round score.
  - `risk_factors` (`array[string]`): Identified risk markers.
  - `immutable_audit_hash` (`string`): SHA-256 cryptographic audit seal.
  - `arbitration_latency_ms` (`float`): Latency in milliseconds ($35.0\text{ ms}$).
